# Interview, journeys, copy: sources

Public sources only. Secondary sources are marked.

**Matt Pocock's skills (https://github.com/mattpocock/skills)**
- `productivity/grilling` — the design tree; the frontier asked in rounds; a recommended answer for each question; facts are the agent's to find; done when the frontier is empty.
- `grill-me` (commit 62f43a1, the original) — one question at a time; explore the codebase instead of asking.
- `grill-with-docs` → `domain-modeling` — challenge fuzzy terms; keep an *Avoid* list.
- `to-spec` — test only external behavior.
- `prototype/LOGIC.md` — state the question; a pure reducer; guided walkthroughs; surface the state.

**Customer discovery and story mapping**
- https://www.momtestbook.com (primary, blurb only) and https://mtlynch.io/book-reports/the-mom-test/ (secondary) — the three rules; compliments, fluff and ideas.
- https://www.christenseninstitute.org/theory/jobs-to-be-done/ — a job is progress within circumstances.
- https://hbr.org/2016/09/know-your-customers-jobs-to-be-done — the source of "hire a product" (paywalled; only the title was checked).
- https://www.intercom.com/blog/using-job-stories-design-features-ui-ux/ — the job story format, and why it replaces persona stories.
- https://www.jpattonassociates.com/the-new-backlog/ — the backbone, the walking skeleton, "context-free mulch".
- https://www.jpattonassociates.com/wp-content/uploads/2015/03/story_mapping.pdf — tasks as verb phrases, slices with outcomes, "look for exceptions".

**Examples and acceptance criteria**
- https://cucumber.io/blog/bdd/example-mapping-introduction/ — the four cards, 25 min, "the one where…".
- https://cucumber.io/docs/gherkin/reference/ — Given/When/Then semantics, `Rule`, tags, 3–5 steps per scenario.
- https://cucumber.io/docs/bdd/better-gherkin/ — declarative over imperative.
- https://gojko.net/2014/05/05/focus-on-key-examples.html — 5–10 key examples, and the boundaries.
- https://gojko.net/2020/03/17/sbe-10-years.html — GWT is a lightweight structure; conversation comes before capture.
- https://alistairmavin.com/ears/ — the EARS patterns.

**UX writing**
- https://www.nngroup.com — error-message guidelines, empty-state interface design, confirmation dialogs, indicators/validations/notifications, user journeys vs user flows.
- https://atlassian.design/content/designing-messages — errors (reason, action, consequence; "we"; no "sorry") and empty states.
- https://polaris.shopify.com/content/actionable-language and /error-messages (via web.archive.org, 2024; the live pages now redirect) — verb + noun, confirmations, Save vs Done, when to validate, no "invalid", no modal errors.
- https://m2.material.io/design/communication/writing.html and dialogs (via web.archive.org, 2019) — present tense, numerals, consistent verbs, no "Are you sure?", ≤ 2 actions per dialog.
- https://learn.microsoft.com/en-us/globalization/reference/microsoft-style-guides — per-language localization style guides (address form, sentence-case errors, "cannot" vs "could not", neutral imperative).
- https://www.scotthurff.com/posts/why-your-user-interface-is-awkward-youre-ignoring-the-ui-stack/ (secondary) — the five UI states.
- https://statecharts.dev — hierarchical states.
- https://playwright.dev/docs/test-annotations — tags.
