# Right-sizing: sources

Public sources only.

- https://basecamp.com/shapeup/1.2-chapter-03 — appetite as a time budget; the soft no.
- https://basecamp.com/shapeup/1.3-chapter-04 — breadboarding; shaped work is rough, solved and bounded.
- https://basecamp.com/shapeup/1.4-chapter-05 — rabbit holes: patch, declare out of bounds, cut back.
- https://basecamp.com/shapeup/1.5-chapter-06 — the pitch ingredients (appetite, rabbit holes, no-gos), which shape `sizing.md`.
- https://basecamp.com/shapeup/3.5-chapter-14 — "compare down to baseline"; the scope-hammering questions.
- https://martinfowler.com/bliki/Yagni.html — the costs of build, delay, carry and repair; YAGNI needs malleable code.
- https://mcfunley.com/choose-boring-technology — innovation tokens; known failure modes.
- https://s2.q4cdn.com/299287126/files/doc_financials/annual/2015-Letter-to-Shareholders.PDF — one-way and two-way doors.
- https://evolutionaryarchitecture.com/precis.html — the definition of a fitness function.
- https://sre.google/sre-book/embracing-risk/ — 100% is the wrong target; error budgets.
- https://sre.google/sre-book/service-level-objectives/ — few SLOs; start loose and tighten.
- https://sre.google/sre-book/monitoring-distributed-systems/ — every page must be actionable.
- https://sre.google/sre-book/addressing-cascading-failures/ — retry amplification (4³ = 64).
- https://www.anthropic.com/engineering/building-effective-agents — start simple.
- https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices — "Overeagerness": no handling for scenarios that can't happen, no hypothetical requirements.
- https://code.claude.com/docs/en/best-practices — a reviewer asked to find gaps over-reports.
- https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-5 — "be conservative" causes under-reporting; filter in a separate pass.
- https://code.claude.com/docs/en/code-review — `REVIEW.md` convergence; effort trades coverage for confidence.
- https://docs.cloud.google.com/pubsub/docs/subscription-retry-policy and https://docs.cloud.google.com/pubsub/docs/handling-failures — one platform's backoff and dead-letter defaults.
- https://docs.cloud.google.com/run/docs/configuring/max-retries — one platform's job task retry default (3).
